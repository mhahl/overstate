# cloud-init Salt minion for Overstate

One `#cloud-config` user-data snippet that installs and wires a Salt
minion on **Fedora 44** or **openSUSE Tumbleweed**, pointing it at the
Overstate master trio. Paste it into a VM's `cloudInitNoCloud`
`userData`, set `hostname:`, and let cloud-init do the rest. Proven
end to end on `salt-test-01`: cloud-init done, minion key accepted,
`test.ping` True, highstate applied clean.

Package facts at time of writing:

- Fedora 44 ships `salt-minion` 3007.8 in its base Everything
  repository. No EPEL step is needed.
- openSUSE Tumbleweed ships `salt-minion` 3006.0 in its standard
  repositories.

The install step dispatches on the package manager, so the same file
works on either distribution.

```yaml
#cloud-config
# Base Fedora 44 / openSUSE Tumbleweed guest with Salt minion bootstrap.
#
# Usage: paste into a VM's cloudInitNoCloud userData and set hostname:.
# SSH keys mirror hardware SKs; the salt masters are the
# *.prod.sigaint.au trio with ordered failover.
hostname: CHANGEME

ssh_pwauth: false
package_update: true
package_upgrade: false

users:
  - name: mhahl
    sudo: ALL=(ALL) NOPASSWD:ALL
    ssh_authorized_keys:
      - sk-ecdsa-sha2-nistp256@openssh.com AAAAInNrLWVjZHNhLXNoYTItbmlzdHAyNTZAb3BlbnNzaC5jb20AAAAIbmlzdHAyNTYAAABBBFbNXF81/IgFb74l2uptFfRNJaKvRZ5TKtpX/W+wqtc7tXzCLHzTxQJBhZIoqhnSIg8arC8w6exHmCrwkZetQGkAAAAEc3NoOg== Mark Hahl <mark.hahl@sigaint.au>
      - sk-ssh-ed25519@openssh.com AAAAGnNrLXNzaC1lZDI1NTE5QG9wZW5zc2guY29tAAAAIOegI4lEpCI30T4DgzJEk3W1NF+VhhoBeaoA23w51bQxAAAABHNzaDo= Mark Hahl Token2 <mark.hahl@sigaint.au>

write_files:
  - path: /etc/salt/minion
    owner: root:root
    permissions: '0644'
    content: |
      # Salt Minion Configuration for Overstate
      # Generated by cloud-init. Shared by Fedora 44 and openSUSE
      # Tumbleweed.

      # Master configuration. NOTE: entries must be bare hostnames OR bare
      # IPs — "hostname IP" pairs on one line are not valid and the minion
      # will fail to resolve them. IPs are used here so bootstrap does not
      # depend on guest DNS. Tried in listed order; the minion fails over
      # to the next one if the current master is unreachable.
      master:
        - 139.99.210.89   # salt-42e5.overstate.syd.prod.sigaint.au
        - 139.99.210.170  # salt-b2b6.overstate.syd.prod.sigaint.au
        - 139.99.149.92   # salt-c010.overstate.syd.prod.sigaint.au

      # Minion id defaults to the guest hostname (set above). Override here
      # only if you need something explicit.
      # id: my-hostname

      log_level: info

runcmd:
  - [systemctl, enable, --now, sshd]
  - |
    set -eu
    if command -v dnf >/dev/null 2>&1; then
      # Fedora 44: salt-minion is in the base release repository.
      dnf -y install salt-minion
    elif command -v dnf5 >/dev/null 2>&1; then
      dnf5 -y install salt-minion
    elif command -v zypper >/dev/null 2>&1; then
      # openSUSE Tumbleweed: salt-minion is in the standard repositories.
      zypper --non-interactive install salt-minion
    else
      echo "no supported package manager" >&2
      exit 1
    fi
  - [systemctl, enable, --now, salt-minion]
  - journalctl -u salt-minion -n 20 --no-pager || true
```

After first boot, accept the minion's key in Overstate (Keys page), then
`test.ping` it. Deleting the VM and re-provisioning the same hostname
reuses the accepted key; a fresh hostname needs a fresh acceptance.
