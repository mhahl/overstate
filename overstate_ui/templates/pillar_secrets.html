Setup

    {% if renderer is none %}
  1. Enable the gpg renderer in master.conf: set renderer: jinja | yaml | gpg and gpg_keydir: /home/salt/data/keys/gpgkeys (see docs/guides/pillar-encryption.md).
    2. {% elif not (renderer.renderer and renderer.keydir) %}
  2. Master config is missing the gpg renderer, the keydir, or both. In Master settings, add renderer: jinja | yaml | gpg and gpg_keydir: /home/salt/data/keys/gpgkeys, then restart the masters.
    3. {% else %}
  3. gpg renderer + keydir detected in master config. ok
    4. {% endif %}
  4. Generate the master keypair — accordion below — and import the private key on all three masters, then check it:
    Generate the master keypair (offline workstation) 
    gpg --quick-generate-key "overstate-pillar" rsa4096 cert never
    KEYID=$(gpg --list-keys --with-colons overstate-pillar | awk -F: '/^pub:/{getline; print $10; exit}')
    gpg --export --armor -o pillar-gpg.pub "$KEYID"
    gpg --export-secret-keys --armor -o pillar-gpg.key "$KEYID"
    NS=overstate
    KEYDIR=/home/salt/data/keys/gpgkeys
    for POD in salt-master-0 salt-master-1 salt-master-2; do
      kubectl cp pillar-gpg.key $NS/$POD:/tmp/pillar-gpg.key
      kubectl exec -n $NS $POD -- bash -c "
        install -d -m 0700 -o salt -g salt $KEYDIR &&
        runuser -u salt -- gpg --homedir $KEYDIR --batch --import /tmp/pillar-gpg.key &&
        shred -u /tmp/pillar-gpg.key &&
        runuser -u salt -- gpg --homedir $KEYDIR --list-secret-keys"
    done

    Back up pillar-gpg.key offline. Each pod should list the overstate-pillar secret key.

    5. {% if not pk_stored %}
  5. Store the master public key (pillar-gpg.pub): Encrypted pillar key settings.
    6. {% endif %}
